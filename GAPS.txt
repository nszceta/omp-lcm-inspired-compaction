OMP LCM INSPIRED COMPACTION: KNOWN GAP REGISTER
================================================

Scope
-----

This file records known gaps in the current released implementation. It ranks
gaps by operational severity. The ordering within a severity class is
intentional.

Severity definitions
--------------------

P0 - Release blocker: correctness or integration is not sufficiently proven
     for production use.
P1 - High: material continuity, security, availability, cost, or compatibility
     risk. A production deployment needs an explicit acceptance decision.
P2 - Medium: important functional or operational limitation with a usable
     workaround.
P3 - Low: maintainability, ergonomics, or observability weakness that does not
     normally threaten retained history.

P0: RELEASE BLOCKERS
====================

CLOSED GAP-003: Replay identity was gated only by provider name
-------------------------------------------------------------
Closure:
  Native replay now persists `ompLcmNativeReplayLineageV1` beside encrypted
  replacement history. The lineage records the provider, effective compaction
  model ID, Responses API/transport variant, normalized effective endpoint, and
  a SHA-256 credential identity. OAuth identities derive from stable non-secret
  credential/account/organization metadata, with token hashing only as a
  conservative fallback when the registry exposes no stable identity.

  Previous encrypted replacement history is seeded only when every lineage
  field matches. Legacy preserve data and model, API variant, endpoint, account,
  organization, or credential changes retain textual LCM continuity but start a
  fresh provider-native lineage.

CLOSED GAP-004: Actual OMP context reconstruction is integration-tested
-----------------------------------------------------------------------
Closure:
  Deterministic integration coverage now persists replacement history through
  OMP's `SessionManager`, closes and reopens the session, and executes the real
  `buildSessionContext` reconstruction. The active compaction summary is
  asserted to carry the exact `openaiResponsesHistory` provider payload.

  The rebuilt OMP messages then pass through OMP's `convertToLlm` and the real
  OpenAI Responses stream implementation. A fetch boundary assertion proves
  that the next provider request contains the exact preserved native history,
  including encrypted compaction data, followed by the new user turn.

P1: HIGH-SEVERITY GAPS
======================

CLOSED GAP-005: Codex session and compaction context is not forwarded
--------------------------------------------------------------------
Current behavior (pre-closure):
  `requestOpenAiRemoteCompaction` is called without `sessionId`,
  `providerSessionState`, or `codexCompaction`. The upstream helper still adds
  basic Codex authentication and attestation headers.

Why it matters:
  Codex compatibility metadata can be session-sensitive. Omitting it may reduce
  cache continuity, omit required request identity, or cause a provider to
  reject encrypted state even when basic authentication succeeds.

Closure:
  The direct v1 replay request now passes the session id through OMP's
  published options argument (`{ sessionId }`), so the codex compatibility
  metadata on the compaction request carries the session routing the main
  loop uses. The v2 orchestrator path already forwarded the session id.
  Regression test asserts the forwarded value reaches the v1 call.

CLOSED GAP-006: Credential refresh and authenticated retry are missing
---------------------------------------------------------------------
Current behavior (pre-closure):
  The plugin obtains one API key from `modelRegistry` and calls the remote
  compaction helper directly. OMP's built-in compaction path wraps calls with its
  authentication retry logic.

Closure:
  Leaf/root summary calls now run through `withAuth(keySource, attempt)` where
  `keySource` is the registry's own auth-retry resolver
  (`modelRegistry.resolver(model, sessionId)`; storage-level resolver and a
  refresh-aware `getApiKey` wrapper are the degraded fallbacks) seeded with the
  tier snapshot via `seedApiKeyResolver`. A 401 force-refreshes the same
  account, a 403/usage-limit rotates to a sibling, and the last auth error is
  recorded in status (`lastLeafModelError`/`lastRootModelError`) instead of
  being silently swallowed. Static keys keep the single-attempt behavior.
  Live-verified on openai-codex/gpt-5.3-codex-spark: leaf and root summaries
  completed as model prose with zero deterministic fallback.

  Tier availability now uses the same credential machinery as the call: the
  gate resolves through `modelRegistry.resolver` via `resolveApiKeyOnce` when
  the registry exposes one (bare `getApiKey` registries keep the snapshot
  gate), and the registry's keyless-provider sentinel (`kNoAuth`, "N/A") is
  rejected instead of being treated as a usable key.

CLOSED GAP-007: OpenAI V2 streaming replay and migration were missing
--------------------------------------------------------------------
Closure:
  Eligible models now delegate provider-native replay to OMP's published
  compaction orchestrator. OMP selects streaming V2 ahead of V1, builds the
  provider request, applies retained-message limits, carries the session's
  active thinking effort, and stores the returned preserve data.

  Replay lineage now distinguishes V1 from V2 and records the mechanism's
  effective endpoint. Previous replay is supplied to OMP only when provider,
  model, API variant, mechanism, endpoint, and credential identity all match;
  otherwise the plugin strips the stale replay while retaining textual LCM
  state. Live Spark and Luna integration tests require persisted encrypted V2
  replacement history, and the Spark-to-Luna switch requires a fresh lineage.

GAP-008: Generic remote compaction endpoints are bypassed
--------------------------------------------------------
Current behavior:
  Returning a complete extension result bypasses OMP's configured generic
  remote endpoint. The plugin explicitly restores only eligible OpenAI Responses
  native compaction.

Why it matters:
  Users configured for self-hosted summarizers, OpenAI-compatible chat servers,
  or other remote compaction endpoints silently receive local LCM summaries
  instead of their configured remote behavior.

Required closure:
  Add explicit support for OMP's published generic remote-compaction API, with a
  clear precedence policy between LCM summarization, OpenAI native replay, and a
  configured generic endpoint.

GAP-009: Existing archived encrypted metadata cannot be backfilled into replay
---------------------------------------------------------------------------
Current behavior:
  Exact raw artifacts preserve `thinkingSignature`, `encrypted_content`, and
  provider payloads, but the plugin starts native replay only from current
  compaction messages or a recognized prior replacement history.

Why it matters:
  Arbitrary encrypted reasoning fields are not equivalent to a valid ordered
  remote-compaction replacement history. Sessions compacted before native replay
  support cannot safely recover provider-native continuity for their old turns.

Required closure:
  Do not guess or splice arbitrary encrypted fields. Backfill only if OMP exposes
  a validated native-history reconstruction API that can rebuild ordered
  call/result and reasoning items from archived entries. Otherwise document the
  first native replay as a new lineage boundary.

GAP-010: Native replay payload size is not bounded or reported
-------------------------------------------------------------
Current behavior:
  Replacement history is stored in compaction preserve data without a plugin
  byte ceiling. Diagnostics report item count but not serialized bytes, item
  types, or growth between generations.

Why it matters:
  Large preserve data increases session-file size, context reconstruction cost,
  memory usage, and startup risk. Item count alone does not identify one very
  large encrypted item.

Required closure:
  Measure serialized bytes and item-type counts before installation, expose them
  in status and dump output, define a defensive maximum, and degrade to textual
  LCM without installing oversized replay data.

GAP-011: Raw artifacts contain plaintext sensitive data at rest
--------------------------------------------------------------
Current behavior:
  Raw JSONL artifacts preserve exact prompts, tool results, filesystem content,
  and other session entries. Provider reasoning may be encrypted, but ordinary
  user and tool content is not encrypted by this plugin.

Why it matters:
  Session artifacts can contain credentials, proprietary source, personal data,
  and command output. Filesystem compromise or overly broad permissions expose
  the full archived conversation.

Required closure:
  Define the artifact store's security boundary, verify restrictive permissions,
  support encryption at rest where OMP permits it, and provide retention and
  secure-deletion controls. Never weaken exact retrieval silently.

GAP-012: Multi-artifact compaction is not transactional
------------------------------------------------------
Current behavior:
  Raw, leaf, and parent artifacts are written sequentially. A later failure
  cancels installation of the new preserve state, but earlier writes can remain
  as unreachable orphan artifacts.

Why it matters:
  Repeated failures can leak disk space and sensitive content. There is no atomic
  commit spanning artifact writes and compaction installation.

Required closure:
  Use an OMP transaction API if one becomes public. Until then, record a pending
  write set and add safe orphan discovery and garbage collection that never
  deletes artifacts reachable from any installed root.

Status (2026-08-01): Part V mitigation shipped — raw artifacts are written
  only immediately before their leaf node, so an abort before the first node
  write leaves zero artifacts; rollback/GC still blocked on a public OMP
  transaction API.

GAP-013: Local semantic summarization and native replay are sequential
--------------------------------------------------------------------
Current behavior:
  The plugin completes raw capture, semantic leaf summaries, DAG condensation,
  and then the provider-native remote request.

Why it matters:
  Eligible compactions pay both model costs and their latencies serially. Large
  compactions can block the user substantially longer than either path alone.

Required closure:
  Run independent local summarization and native remote compaction concurrently
  after source selection, with shared cancellation and fail-isolated results.
  Preserve the rule that remote failure cannot invalidate a valid textual LCM
  result.

GAP-014: Fail-closed behavior trades continuity for availability
---------------------------------------------------------------
Current behavior:
  After accepting `session_before_compact`, boundary errors, artifact failures,
  missing textual-summary credentials, and unsupported explicit renderers return
  `{ cancel: true }`. The plugin never falls through to OMP's built-in path.

Why it matters:
  This prevents accidental double compaction and partial installation, but a
  plugin-specific failure can leave the session unable to compact until the
  cause is fixed or the plugin is disabled.

Required closure:
  Keep fail-closed as the default. Add explicit operator guidance, actionable
  error codes, and a deliberate command or configuration for disabling LCM
  before retrying with OMP's built-in compaction. Never fall through silently.

GAP-015: Deterministic fallback preserves bytes, not semantic continuity
-----------------------------------------------------------------------
Current behavior:
  When model summarization cannot converge, the plugin stores a bounded source
  excerpt and marks summary quality as `deterministic-fallback`. Exact history
  remains retrievable from raw artifacts.

Why it matters:
  The active model may lose decisions or unresolved work that fall outside the
  excerpt. Retrieval is possible but is not guaranteed to happen automatically.

Required closure:
  Add visible degradation warnings, targeted retry of failed leaves, and a repair
  command that can rebuild degraded nodes once a summarization model is
  available. Keep exact raw artifacts as the authority.

P2: MEDIUM-SEVERITY GAPS
========================

CLOSED GAP-016: Native replay degradation is not proactively surfaced
--------------------------------------------------------------------
Current behavior (pre-closure):
  `/lcm status` and `/lcm dump` expose replay status and a bounded error, but a
  remote replay failure does not produce a dedicated user warning when textual
  LCM succeeds.

Why it matters:
  Operators can unknowingly continue without provider-native continuity.

Closure:
  A native replay failure (exception or internal-deadline skip) now emits a
  concise notification with the bounded reason through the session's notify
  channel (`LCM native replay failed: <reason>`), once per run, while the
  textual LCM result still completes. No encrypted payload content is ever
  included.

GAP-017: No asynchronous soft-threshold or background compaction
---------------------------------------------------------------
Current behavior:
  Compaction runs synchronously in the public `session_before_compact` hook.

Why it matters:
  Work begins only when OMP invokes compaction and blocks that operation. The
  plugin cannot summarize ahead of the hard context boundary or install a result
  atomically in the background.

Required closure:
  Requires public OMP lifecycle and transaction APIs for background planning,
  cancellation, and atomic installation.

GAP-018: Handoff, shake, and automatic pre-handoff injection are unsupported
-------------------------------------------------------------------------
Current behavior:
  Automatic LCM targets ordinary `context-full` and `snapcompact` events.
  Handoff and shake execute outside or before the ordinary custom result path,
  and the extension cannot inject source automatically before handoff.

Why it matters:
  Users choosing those strategies do not receive equivalent LCM archival and
  replay behavior.

Required closure:
  Add support only when OMP exposes public handoff/shake lifecycle hooks and a
  safe source-injection contract. Document explicit supported strategies until
  then.

GAP-019: Automatic renderer selection cannot observe hidden OMP guidance
------------------------------------------------------------------------
Current behavior:
  `renderer=auto` uses public strategy, custom-instruction, and model-vision
  information. Internal OMP guidance overrides are not exposed to extensions.

Why it matters:
  Auto selection can differ from an internal OMP decision in edge cases.

Required closure:
  Use an explicit renderer for deterministic behavior, or consume a future
  public resolved-action field from OMP.

GAP-020: Artifact IDs are session-scoped rather than globally unique
--------------------------------------------------------------------
Current behavior:
  DAG links use numeric artifact IDs assigned by the session artifact manager.

Why it matters:
  An ID copied between sessions can resolve to unrelated content or nothing.
  External indexes cannot treat `artifact://86` as a global identity.

Required closure:
  Include a session identity in external references or adopt a public globally
  unique artifact identifier if OMP provides one.

GAP-021: Retrieval is available but not guaranteed to occur
-----------------------------------------------------------
Current behavior:
  Active context contains bounded root summaries and retrieval instructions.
  The model must choose `lcm_expand`, `read`, or `grep` when exact archived detail
  is needed.

Why it matters:
  A model can answer from an incomplete summary without retrieving authoritative
  history.

Required closure:
  Add policy-driven retrieval triggers or pre-turn relevance lookup when a public
  hook permits it. Keep exact citations to artifact IDs in retrieved answers.

Status (2026-08-01): PARTIALLY CLOSED — PLAN.md Part III Candidate B
  (`lcm_grep`) shipped: node-grouped, paginated, `summaryId`-scoped regex
  search over reachable raw history (src/tools.ts, test/tools.test.ts),
  reducing the guessing burden. Policy-driven triggers still need public hooks;
  unscheduled. `lcm_grep` patterns are agent-supplied tool arguments
  (semi-trusted, grep-tool norm); catastrophic-backtracking regexes are the
  caller's responsibility, matching ordinary OMP grep behavior.

GAP-022: Dump and expansion limits can hide deep or wide history
---------------------------------------------------------------
Current behavior:
  DAG inspection has depth, node-count, output-size, raw-preview, and summary
  preview limits. `/lcm dump` intentionally favors a structural overview.

Why it matters:
  A single dump does not prove every descendant is readable and can omit the
  branch containing a sought detail.

Required closure:
  Keep limits for safety, but expose truncation counts and continuation root IDs
  consistently so callers can expand the omitted branch deliberately.

GAP-023: No orphan garbage collection or retention policy
---------------------------------------------------------
Current behavior:
  Artifacts are retained for the session lifetime. The plugin does not enumerate
  unreachable nodes, expire old raw history, or report retained bytes.

Why it matters:
  Long-running or failure-prone sessions can accumulate disk usage indefinitely.

Required closure:
  Add reachability analysis from every installed preserve root, dry-run reporting,
  configurable retention, and safe deletion integrated with the session store.

Status (2026-08-01): Part V observability shipped — `lastOrphanArtifactCount`
  reports files not referenced by any installed node or root at run start;
  safe deletion still blocked on a public OMP delete API.

GAP-024: Preserve-state schema evolution has no migration framework
-------------------------------------------------------------------
Current behavior:
  LCM preserve state accepts schema version 1. Unknown versions are rejected.
  Replay lineage additions do not yet have a versioned plugin-owned schema.

Why it matters:
  Future changes to root metadata or replay identity can strand older sessions or
  require ad hoc marker-based repair.

Required closure:
  Define explicit versioned migrations, retain forward-compatible unknown fields
  where safe, and test upgrades from every released preserve schema.

GAP-025: Snapcompact integration is summary-only
------------------------------------------------
Current behavior:
  The plugin feeds bounded LCM root text to snapcompact as a synthetic message.
  It does not generate or retain visual frames from raw historical messages;
  `lastSnapcompactFrameCount` is normally zero.

Why it matters:
  Users expecting snapcompact's visual-frame archive do not receive it. Historical
  images remain only where exact raw session artifacts preserve them.

Required closure:
  Either keep and clearly label summary-only behavior, or implement frame
  generation and preservation with explicit memory and payload limits.

GAP-026: Replay and compaction telemetry is minimal
--------------------------------------------------
Current behavior:
  Runtime status reports the latest outcome, item count, provider, and bounded
  error. It does not report duration, request bytes, response bytes, retry count,
  provider cost, item types, or per-stage latency.

Why it matters:
  Operators cannot distinguish slow local summaries from remote transport, track
  replay growth, or set reliable alerts and budgets.

Required closure:
  Add structured, secret-safe metrics for source capture, leaf summarization,
  DAG condensation, native replay, payload sizes, and total compaction latency.

Status (2026-08-01): PARTIALLY CLOSED — PLAN.md Part II's runtime-status
  contract landed: lastStartedAt, lastElapsedMs, lastLeafSummaryModel,
  lastRootSummaryModel, lastRawChunkCount, lastSummaryBatchCount,
  lastSummaryConcurrency, lastCompletedModelSummaryCount,
  lastDeadlineFallbackCount, lastDeadlineStage (src/controller.ts,
  test/controller-deadline.test.ts). Full structured metrics (latency per
  stage, payload sizes, retry counts) remain unscheduled.

P3: LOWER-SEVERITY GAPS
=======================

CLOSED GAP-027: Runtime diagnostics are ephemeral
------------------------------------------------
Current behavior (pre-closure):
  `/lcm status` describes only the latest in-memory controller state. Reloading
  the extension or restarting OMP clears it, although installed compaction
  preserve data remains in the session.

Why it matters:
  Post-restart debugging loses the last failure and timing context.

Closure:
  Each run persists a bounded diagnostic snapshot as a session custom entry
  (`lcm-status`, versioned, with the status copied at write time), and
  registration hydrates the most recent entry into the live status so
  `/lcm status` and `/lcm dump` keep reporting the last run across reloads.
  The payload carries no credentials or full payloads; persistence is
  best-effort and never fails compaction. Round-trip covered by unit tests.

GAP-028: Settings persistence probes multiple manager methods dynamically
------------------------------------------------------------------------
Current behavior:
  Renderer persistence adapts to several possible plugin-manager method names at
  runtime.

Why it matters:
  API drift is discovered only during command execution and can make
  `/lcm renderer` fail even though compaction itself still runs.

Required closure:
  Bind to one published typed settings API for the supported OMP version and add
  an integration test for persistence across reload.

CLOSED GAP-029: The extension remains tightly coupled to OMP 17.1.8
------------------------------------------------------------------
Current behavior (pre-closure):
  Runtime and peer dependencies are pinned to OMP 17.1.8 public APIs.

Why it matters:
  Newer OMP releases may alter compaction preparation, provider history, tool
  registration, or session reconstruction contracts. Older releases are not
  supported.

Closure:
  All `@oh-my-pi/*` pins (dependencies, peer, dev) moved to 17.2.3; the full
  suite and the live integration harness now run against 17.2.3. The auth-retry
  APIs used by the GAP-006 closure (`ApiKeyResolver`, `seedApiKeyResolver`,
  `withAuth`, `ModelRegistry.resolver`) exist in both 17.1.8 and 17.2.3, so the
  plugin remains compatible with both lines while targeting 17.2.3+.

GAP-032: Tier-resolved models were passed to the completion wrapped in metadata
-----------------------------------------------------------------------------
Current behavior (pre-fix):
  `resolveSummaryModel` returns `ResolvedSummaryModel.model` as a
  `TierModelInfo` wrapper (`{ model, provider, id, label, contextWindow }`), but
  the controller passed that wrapper straight to `complete()`. The wrapper has
  no `api` field, so every tier-resolved call died in pi-ai's dispatch with
  `Unhandled API: undefined` and every summary degraded to the deterministic
  fallback. This is what the 2026-07-28/08-01 live smokes actually hit: the
  active codex model resolved fine (with a key), the call failed before any
  HTTP request, and the swallowed error hid it. Unit tests missed it because
  every injected completion fake ignores the model argument.

Closure:
  The controller now unwraps (`leafModel.model.model` / `rootModel.model.model`)
  before calling the completion, with a unit regression that asserts the fake
  receives the unwrapped candidate including its `api` field, and a live test
  asserting model-quality summaries on openai-codex/gpt-5.3-codex-spark.

GAP-030: No automated live release canary
-----------------------------------------
Current behavior:
  Unit, integration-shaped, and local smoke tests run before release, but no
  post-release automation installs the marketplace tag into a clean OMP profile
  and exercises compaction.

Why it matters:
  Packaging, marketplace metadata, dependency installation, or extension reload
  can fail despite source tests passing.

Required closure:
  Add a release canary that installs the tagged marketplace version, verifies
  `/lcm version`, performs local compaction, inspects the DAG, and optionally runs
  a credentialed native-replay canary in a protected environment.

Status (2026-08-01): CLOSED — `scripts/canary.ts` (`bun run canary`) packs the
  plugin, extracts the tarball, installs the packed directory into a clean
  temporary OMP profile (fresh `OMP_PROFILE`; profile and temp state removed
  on the way out), verifies the install via `omp plugin list`, and runs the
  opt-in live integration (`LCM_LIVE_INTEGRATION=1`), exiting non-zero on any
  step failure; the manual live loop remains the documented exception.

GAP-031: No type-aware exploration summaries for oversized tool results
----------------------------------------------------------------------
Current behavior:
  OMP spills oversized tool results (above `tools.artifactSpillThreshold`,
  default 50 KiB) to session artifacts with head+tail elision and an
  `[raw output: artifact://N]` footer (output-meta.ts
  `spillLargeResultToArtifact`). The plugin's raw capture retains the elided
  view plus `details.meta.truncation.artifactId`. No semantic exploration
  summary (JSON/CSV/SQL schema+shape, code structure, prose summary) is
  generated anywhere; the model must read `artifact://N` directly to learn
  what the elided middle contains.

Why it matters:
  Elided content is recoverable but opaque: the model does not know the
  schema, shape, or structure of the omitted bytes without opening the
  artifact. This is the OMP-terms version of the paper's large-file gap.

Required closure:
  Implement the lazy type-aware exploration summary in the proposed
  `lcm_describe` tool (PLAN.md Part III Candidate A), on demand and bounded,
  with no capture-time work inside the compaction hook.

Status (2026-08-01): CLOSED — Candidate A shipped: `lcm_describe` explore mode
  produces type-aware exploration summaries (JSON key/type/count extraction,
  CSV columns/rows, SQL statement kinds and table names, code signatures,
  prose via the active model with abort-safe head/tail degradation) in
  src/explore.ts and src/tools.ts, covered by test/explore.test.ts and
  test/tools.test.ts. Metadata-only mode performs no model call.

CLOSED GAP-032: OMP's fixed 30s handler wall can abort the compaction hook
------------------------------------------------------------------------
Current behavior (pre-closure):
  OMP's extension runner aborts `session_before_compact` handlers after a
  fixed 30 000 ms and falls back to built-in compaction. The plugin's internal
  deadline (default 24 s) bounded only the leaf/root summary calls: config
  loading, the API-key preflight, raw capture, orphan accounting, tier
  resolution, the DAG write loop, the provider-native replay call, and
  snapcompact rendering were bounded only by OMP's 30 s signal, so a slow
  native compaction call ran the handler into the wall. Observed in the field:
  `Extension ... handler timed out after 30000ms` (event session_before_compact,
  OMP log 2026-08-01); the run produced no persisted status (`/lcm status`
  returned `{}`) and its artifacts became unreachable orphans.

Why it matters:
  A timed-out handler silently forfeits the whole run — no LCM result, no
  status, no preserve data — and wastes the provider-native work already done.

Required closure:
  Bound the entire handler by one absolute wall-clock deadline (config
  `handlerDeadlineMs`, max 27 s < 30 s) measured from handler start, and
  degrade gracefully (deterministic fallbacks, native replay skipped, status
  persisted) instead of letting aborts escape to the harness wall.

Status (2026-08-01): CLOSED — `beforeCompact` now creates a prelude deadline
  (4 s) racing config loading (defaults on expiry) and an absolute total
  deadline from handler start; `total.signal` is wired into the API-key
  preflight, capture, orphan accounting, tier resolution, root model calls,
  the native replay call (with a `raceWithSignal` guarantee for
  signal-ignoring callees), and snapcompact rendering. Tier resolution and the
  DAG write loop treat internal expiry as degradation, not cancellation:
  tier lookups fall back to the active model and the write loop checks only
  user cancellation. Deadline aborts persist status and return
  `{ cancel: true }` quickly instead of reaching OMP's 30 s wall. Regression
  tests in test/controller.test.ts (never-settling native replay; hanging
  config loader) fail on the pre-closure code and pass post-closure; the live
  integration suite still completes with model-quality summaries and native
  replay preserved.

Ranking notes
-------------

- Exact raw preservation prevents irreversible conversational data loss, but it
  does not make every semantic or provider-native continuity failure harmless.
- Textual LCM fallback is the primary safety net for native replay failure.
- P0 items should be closed before claiming production-ready provider-native
  replay. P1 items require explicit risk acceptance even after P0 closure.
- Some P2 limitations require new public OMP APIs and cannot be solved entirely
  inside a standalone extension today.
